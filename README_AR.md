# قفل الكود الأول — 0.1.0 تجريبي

مشروع تطبيق أندرويد مستقل مكتوب بـ Kotlin، وليس تعديلًا أو نسخة من كود AppLock Pro.

## حالة التسليم

نجح بناء APK التجريبي في GitHub Actions بتاريخ 2026-10-22، مع نجاح اختبارات JVM وAndroid Lint والتحقق من توقيع APK v2. صلاحية المستخدم الوحيدة في ملف APK هي USE_BIOMETRIC؛ لا توجد صلاحية INTERNET. لم يتم اختبار التطبيق على هاتف أو محاكي بعد، ويلزم إكمال اختبار القبول أدناه.

البناء المتحقق منه: https://github.com/firstcodesa/firstcode-lock/actions/runs/39715671508

## الوظائف المكتوبة

- واجهة عربية RTL واختيار التطبيقات والبحث والوضع الفاتح/الليلي.
- رمز من ستة أرقام، إنشاء وتأكيد وتغيير، ولوحة أرقام داخل التطبيق.
- تخزين مشتق PBKDF2-HMAC-SHA256 بعدد 210000 دورة مع ملح عشوائي؛ لا تخزين للرمز كنص.
- انتظار 30 ثانية بعد خمس محاولات خاطئة؛ حالة المحاولات محفوظة محليًا.
- فتح اختياري بالتحقق الحيوي المسجل في أندرويد، وتأكيد قبل تفعيله.
- إعادة القفل عند الانتقال لتطبيق آخر، أو صلاحية فتح دقيقة/خمس دقائق. إطفاء الشاشة يمحو الجلسات.
- موافقة صريحة قبل فتح إعدادات إمكانية الوصول، مع خيار إلغاء الموافقة وتعطيل الخدمة.
- خدمة ترصد اسم التطبيق فقط: لا قراءة لشجرة المحتوى ولا تسجيل لمحتوى الرسائل أو ضغطات المفاتيح.
- لا صلاحية INTERNET، ولا مكتبات إعلانات أو تحليلات أو اتصالات خارجية.
- التطبيق لا يقفل إعدادات النظام أو الشاشة الرئيسية أو تطبيقات الاتصال.

## بناء APK عبر GitHub

1. أنشئ مستودعًا **خاصًا** باسم `firstcode-lock` مع README لتكون له نقطة بداية.
2. ارفع محتويات هذا المجلد إلى جذر المستودع، مع مجلد `.github`.
3. ادخل Actions وافتح `Build FirstCode Lock APK`. يبدأ العمل تلقائيًا عند رفع الكود أو بواسطة Run workflow.
4. سير العمل يشغّل اختبارات JVM وAndroid Lint ثم يبني APK تجريبيًا موقعًا بمفتاح debug.
5. بعد نجاح المهمة، نزّل artifact باسم `FirstCode-Lock-0.1.0-test-APK` وفك ZIP لتحصل على APK وملف SHA256.

يتطلب الحساب إمكانية تشغيل GitHub Actions وتوفر حصة تشغيل للمستودعات الخاصة. لا يشمل سير العمل نشرًا عامًا أو رفعًا إلى متجر التطبيقات.

## بناء محلي

المتطلبات: JDK 17 الكامل، Android SDK 35، Build Tools 35.0.0، Gradle 8.11.1.

```sh
gradle :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

ملف APK الناتج: `app/build/outputs/apk/debug/app-debug.apk`.

المشروع لا يحتوي Gradle Wrapper ثنائيًا. افتح المشروع ببيئة توفر Gradle 8.11.1 أو استخدم GitHub Actions الذي يثبته.

## التشغيل واختبار القبول المطلوب

الحد الأدنى Android 9 / API 28. يستهدف التطبيق SDK 35. يلزم اختبار فعلي خصوصًا على Samsung Android 16.

1. تثبيت APK التجريبي، إنشاء رمز وتأكيده، والتأكد أن الرمز الخاطئ يُرفض.
2. تجربة 5 أخطاء ثم الانتظار؛ إغلاق وفتح التطبيق لا يلغي التأخير.
3. تفعيل خدمة إمكانية الوصول بعد قراءة الموافقة. بعض الأجهزة قد تتطلب السماح بالإعدادات المقيّدة لتطبيق مثبت يدويًا، طبقًا لإعدادات الجهاز.
4. اختيار تطبيق غير حساس للاختبار. اختباره من المشغل والإشعار والتطبيقات الأخيرة.
5. تجربة الرجوع وإيماءة الرجوع وHome وتدوير الشاشة قبل التحقق: يجب ألا يمنح أي منها جلسة فتح.
6. الفتح الصحيح ثم الانتقال إلى Home والعودة يجب أن يعيد القفل في الوضع الفوري.
7. اختيار مهلة دقيقة: تأكد من الفصل بين التطبيقات وانتهاء المهلة ومسح الجلسة بعد إطفاء الشاشة.
8. اختبار البصمة الناجحة والفاشلة والإلغاء والجهاز دون بصمة مسجلة.
9. الانتقال لخلفية لوحة الإدارة ثم العودة يجب أن يطلب التحقق مجددًا.
10. إعادة تشغيل الجهاز والتأكد من عودة الخدمة، واختبار أوضاع البطارية في الشركة المصنّعة.
11. اختبار الوضعين الفاتح والداكن، العربية، الخط الكبير، الشاشات الصغيرة والتقسيم المتعدد.

## حدود الحماية

هذه طبقة خصوصية إضافية وليست حماية أمنية يستحيل تجاوزها. تعطيل الخدمة أو إزالة التطبيق أو مسح بياناته أو تشغيل الوضع الآمن يتجاوز الحماية. قد يظهر التطبيق المستهدف للحظة قبل نافذة القفل. لا يخفي التطبيق محتوى إشعارات التطبيقات الأخرى أو صورها في قائمة التطبيقات الأخيرة، وقد تختلف موثوقية رصد التطبيقات مع النوافذ المتعددة والشركة المصنّعة. يستخدم أندرويد مصادقة الجهاز الحيوية؛ كل بصمة مسجلة على الجهاز قد تكون مقبولة. فعّل قفل الجهاز نفسه وإخفاء محتوى الإشعارات عند الحاجة.

## التوقيع والإصدار

المهمة تنتج **debug APK للاختبار فقط**. قد يتغير مفتاح debug بين عمليات البناء، مما يتطلب إزالة النسخة السابقة وإعادة إعدادها. قبل إصدار دائم ينبغي إنشاء مفتاح توقيع ثابت يملكه صاحب المشروع، وحفظه خارج Git مع نسخة احتياطية، وتكوين release signing واختبار الإصدار النهائي. لا توجد مفاتيح أو بيانات دخول افتراضية في الحزمة.

## الملفات

- `app/src/main/java/sa/firstcode/lock`: الواجهات، الحماية، الإعدادات، والتشفير الاشتقاقي.
- `app/src/test`: اختبارات اشتقاق الرمز وجلسات إعادة القفل.
- `.github/workflows/android.yml`: بناء واختبار وإرفاق APK.
- `VALIDATION.json`: نتائج فحص البنية المحلي، دون ادعاء نجاح بناء APK.

## تحديث 0.2.0
واجهة محسنة ونصوص مختصرة، مع اسم المبرمج: أبوغازي العتيبي. حماية إزالة اختيارية عبر مسؤول الجهاز، دون سياسات مسح أو قفل الجهاز. يمكن للمالك تعطيلها من إعدادات أندرويد؛ ليست منعًا نهائيًا للإزالة. يلزم اختبار التفعيل والإلغاء والإزالة على الهاتف.

التوقيع تجريبي؛ قد يلزم حذف النسخة السابقة قبل تثبيت هذه النسخة بسبب اختلاف مفتاح البناء، ثم إعداد الرمز والتطبيقات مجددًا. نتائج البناء أعلاه تخص 0.1.0.

واجهة عربية وإنجليزية؛ إيقاف مؤقت يحتفظ بالاختيارات، تحديد الكل أو إلغاء الكل مع تأكيد، بحث وتصفية المختار، ترتيب المختار أولًا وإخفاء اسم التطبيق في شاشة القفل. تحديد الكل يشمل التطبيقات المتاحة حاليًا فقط؛ التطبيقات الجديدة تحتاج اختيارًا لاحقًا.
